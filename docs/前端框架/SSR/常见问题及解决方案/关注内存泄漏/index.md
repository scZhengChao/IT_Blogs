# 关注内存泄漏

## 目录

- [问题描述](#问题描述)
- [解决方案](#解决方案)

> 在 SSR 场景下，开发者需要特别关注内存泄露问题，即使是微小的内存泄露，在大量的访问后也会对服务造成影响。

打包生成的 SSR Bundle 在服务端仅执行一次，**但是组件渲染逻辑会在每次访问时都执行**。避免在**全局定义任何可能增长的数据结构，或在全局进行事件订阅，或创建不会被销毁的流。**

> 全局定义的变量或者实例；不会被销毁；没次渲染逻辑执行的时候；其实操作的是同一个全局变量或者实例；导致服务端内存的持续增长；

SSR 时，浏览器的每次请求，都会触发服务端重新执行一次组件渲染逻辑。所以，需要避免在**全局定义任何可能不断增长的数据结构**，或在**全局进行事件订阅，或创建不会被销毁的流**。

### 问题描述

服务器端渲染时未正确清理资源导致内存泄漏。

### 解决方案

- 使用`@loadable/component`进行代码分割
- 确保每次请求都创建新的 React 应用实例
- 避免全局状态污染

```javascript 
import loadable from '@loadable/component';

const HeavyComponent = loadable(() => import('./HeavyComponent'));

function App() {
  return (
    <div>
      <HeavyComponent />
    </div>
  );
}
```
