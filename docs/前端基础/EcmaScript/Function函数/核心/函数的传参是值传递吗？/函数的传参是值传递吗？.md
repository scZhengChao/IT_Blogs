**JavaScript 函数的参数传递规则只有一种 —— 严格的值传递**，不存在引用传递。

之所以会有 “好像是引用传递” 的错觉，核心原因是：**传递的值分两种类型**—— 基础类型的**原始值**、引用类型的**内存地址值**，后者的传递方式让我们误以为是引用传递，实际只是传递了 “**指向堆内存的地址值**” 而已。

下面用「类型拆分 + 代码示例 + 核心对比」讲清楚，新手也能一眼看懂。

### 一、先明确 JS 的两大数据类型（传参的基础）

JS 数据类型分两类，传参的本质差异完全由类型决定：

1. **基础类型**：Number、String、Boolean、Undefined、Null、Symbol、BigInt
   - 数据直接存在**栈内存**，变量存储的是**原始值本身**；
2. **引用类型**：Object（包含数组、函数、对象字面量等）
   - **数据存在堆内存，栈内存的变量只存储指向堆内存的地址值（类似门牌号，通过它能找到堆里的实际数据）。**

### 二、基础类型：传参是「原始值的拷贝」（最直观的值传递）

函数接收的是**基础类型值的副本**，函数内部修改这个副本，**不会影响外部原变量**—— 这是值传递的典型特征。

```javascript 
let a = 10;
let b = 'hello';

// 函数内部修改参数
function change(x, y) {
  x = 20;
  y = 'world';
  console.log('函数内：', x, y); // 函数内：20 world
}

change(a, b);
console.log('函数外：', a, b); // 函数外：10 hello 【原变量完全没变化】
```


**原理**：调用`change(a, b)`时，把`a`的原始值`10`、`b`的原始值`hello`拷贝了一份传给`x`、`y`，`x/y`是函数内部的局部变量，和外部`a/b`毫无关联，修改自然互不影响。

### 三、引用类型：传参是「地址值的拷贝」（易被误解为引用传递的核心）

函数接收的是**栈内存中地址值的副本**，这个副本和原变量的地址值**指向同一个堆内存数据**—— 所以函数内部通过地址值修改堆里的实际数据，**外部原变量会跟着变**。

但注意：这**不是引用传递**，只是传递了 “地址值” 的副本；如果在函数内部**修改参数本身的地址值**（让参数指向新的堆内存），外部原变量也不会受影响。

#### 示例 1：修改地址指向的堆数据（外部会变）

```javascript 
let obj = { name: '张三' };
let arr = [1, 2, 3];

function change(o, a) {
  o.name = '李四'; // 修改堆内存中的对象属性
  a.push(4);       // 修改堆内存中的数组元素
  console.log('函数内：', o, a); // 函数内：{name: '李四'} [1,2,3,4]
}

change(obj, arr);
console.log('函数外：', obj, arr); // 函数外：{name: '李四'} [1,2,3,4] 【原数据变了】
```


**原理**：调用`change(obj, arr)`时，把`obj`的地址值、`arr`的地址值拷贝了一份传给`o`、`a`；`o`和`obj`指向同一个堆对象，`a`和`arr`指向同一个堆数组，所以修改堆里的实际数据，外部能感知到。

#### 示例 2：修改参数本身的地址值（外部不变，关键反证）

这是区分**值传递**和**引用传递**的核心：如果是真正的引用传递，修改参数的指向，外部原变量会跟着变；但 JS 中不会。

```javascript 
let obj = { name: '张三' };
let arr = [1, 2, 3];

function change(o, a) {
  // 让参数指向新的堆内存（修改参数本身的地址值）
  o = { name: '王五' };
  a = [4, 5, 6];
  console.log('函数内：', o, a); // 函数内：{name: '王五'} [4,5,6]
}

change(obj, arr);
console.log('函数外：', obj, arr); // 函数外：{name: '张三'} [1,2,3] 【原变量完全没变化】
```


**原理**：函数内的`o = {name: '王五'}`是给参数`o`重新赋值了一个新的地址值，让`o`指向新的堆对象；但这个操作只影响函数内部的局部变量`o`，外部`obj`的地址值完全没变，依然指向原来的堆对象 —— 这是**纯值传递**的铁证。

### 四、关键区分：值传递 vs 引用传递（避免混淆）

很多人搞混，核心是记住这两个定义（JS 只有前者）：

| 传递方式      | 核心特征                                                            | JS 是否支持 |
| --------- | --------------------------------------------------------------- | ------- |
| **值传递**​  | 传递的是「实际值的副本」（基础类型传原始值副本，引用类型传地址值副本）；函数内修改\*\*参数本身\*\*，外部原变量不受影响 | ✅ 唯一支持  |
| **引用传递**​ | 传递的是「变量的内存引用」（相当于给变量起了一个别名）；函数内修改\*\*参数本身\*\*（包括指向），外部原变量会同步变化  | ❌ 完全不支持 |

简单说：**引用传递是传 “变量的别名”，值传递是传 “值的副本”**，JS 从未传过 “别名”，哪怕是引用类型，传的也是 “地址值的副本”。

### 五、补充：特殊的函数参数（按值传递的延伸）

1. **函数作为参数**：函数也是引用类型，传参时同样传递的是**函数地址值的副本**，所以函数内可以调用这个参数函数，也能修改其属性（如果有）；
2. **解构赋值传参**：本质\*\*还是值传递，基础类型解构传原始值副本，\*\***引用类型解构传地址值副本；**

```javascript 
let obj = { name: '张三' };
function change({ name }) { name = '李四'; }
change(obj);
console.log(obj.name); // 张三 【解构的name是基础类型副本，修改无效】
```
