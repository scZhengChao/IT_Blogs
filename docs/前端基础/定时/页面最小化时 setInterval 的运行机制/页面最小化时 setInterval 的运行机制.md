## 主流浏览器的处理方式

1. **Chrome/Firefox/Edge (桌面版)**：
   - 时间间隔 ≥1秒：会降低到每秒最多执行1次（1Hz）
   - 时间间隔 <1秒：多数情况下会暂停执行
   - 完全暂停：当页面完全不可见一段时间后（如几分钟）
2. **Safari**：
   - 更激进，通常会完全暂停所有定时器
3. **移动浏览器**：
   - 通常更加严格，页面不可见时几乎总是暂停定时器

## 背后的原因

浏览器这样做是为了：

- 节省电池电量
- 减少CPU/GPU使用
- 优化系统资源分配
- 提升用户体验（后台标签页不会影响前台操作）

## 特殊情况的处理

1. **Web Workers**：在Worker中的`setInterval`通常不受影响
2. **Audio/Video 播放**：与媒体播放相关的定时器可能保持运行
3. **WebRTC**：实时通信相关的定时器通常保持运行

## 开发者应对方案

如果需要后台持续运行：

```javascript 
// 检测页面可见性
document.addEventListener('visibilitychange', () => {
  if (document.hidden) {
    // 页面隐藏时的处理
  } else {
    // 页面重新可见时的处理
  }
});

// 或者使用Web Worker保持运行
const worker = new Worker('worker.js');
```


## 实际测试建议

由于不同浏览器/版本行为可能不同，建议：

1. 不要依赖最小化时的定时器精度
2. 关键功能应使用`visibilitychange`事件检测状态变化
3. 需要精确计时考虑使用Web Worker

记住：**浏览器可以随时调整这些优化策略，所以不应编写依赖特定后台定时行为的代码。**
