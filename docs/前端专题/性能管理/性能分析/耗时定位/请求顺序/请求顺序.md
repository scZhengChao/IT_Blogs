# 请求顺序

## 目录

你想知道如何在浏览器开发者工具中查看大量请求的加载顺序，这是分析页面资源加载时序、定位并发 / 阻塞问题的关键。以下是清晰、可操作的方法，用表格 + 步骤说明，简洁且易落地：

### 一、核心查看方法（Chrome DevTools）

| 操作方式                 | 操作步骤                                                                             | 作用说明                                       |
| -------------------- | -------------------------------------------------------------------------------- | ------------------------------------------ |
| 1\\. 按时间轴直观查看        | 1\\. 打开 Network 面板 → 确保「Timeline」（时间轴）开启（默认开启）2. 刷新页面，所有请求会按\*\*开始加载的时间\*\*在横轴排列 | 一眼看出请求的先后顺序、重叠（并发）情况，长耗时请求会明显拉长时间轴         |
| 2\\. 按「Start Time」排序 | 1\\. 点击 Network 面板的「Start Time」列标题2. 会按请求\*\*开始加载的时间\*\*正序 / 倒序排列                | 精准排序所有请求，快速定位 “先加载哪些、后加载哪些”，排查是否有优先级错误     |
| 3\\. 按「Waterfall」分组  | 1\\. 点击 Network 面板左上角「Waterfall」下拉框 → 选择「Initiator」2. 请求会按 “发起者” 分组展示            | 查看某一资源（如 index.html）触发的所有子请求的加载顺序，定位链式阻塞问题 |
| 4\\. 筛选 + 排序组合       | 1\\. 先在筛选栏选择资源类型（如 JS/CSS）2. 再点击「Start Time」排序                                   | 聚焦某类资源的加载顺序，排除无关资源干扰（如图片）                  |

### 二、关键辅助技巧

1. **标记请求耗时阶段**：鼠标悬停在 Network 面板中某条请求的时间轴上，会显示该请求各阶段的耗时（如 Queued/SSL/Download），结合顺序可判断 “前一个请求是否阻塞后一个请求”。
2. **查看请求依赖**：右键某条请求 → 选择「Show Initiator Tree」，会以树形结构展示请求的触发关系和顺序，清晰看到 “谁触发了谁”。
3. **Performance 面板更全局**：打开 Performance 面板 → 录制（Record）→ 刷新页面 → 停止录制，在「Network」层可看到所有请求的时间轴和顺序，还能关联 JS 执行、渲染等阶段，判断请求顺序是否影响页面渲染。

### 总结

1. 快速看顺序：优先用 Network 面板的「Timeline 时间轴」或点击「Start Time」列排序；
2. 看依赖顺序：用「Waterfall→Initiator」分组或「Show Initiator Tree」；
3. 结合耗时阶段：通过悬停时间轴，判断请求顺序是否导致阻塞（如前一个请求占满并发数，后一个排队）。
