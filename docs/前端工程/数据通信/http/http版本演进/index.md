HTTP（HyperText Transfer Protocol）是互联网上应用最广泛的协议之一，自1991年诞生以来经历了多个版本的迭代，主要版本包括**HTTP/0.9、HTTP/1.0、HTTP/1.1、HTTP/2**和**HTTP/3**。以下是各版本的核心区别和关键改进：

***

### 1.**HTTP/0.9（1991年）**

- **特点**：最初版本，极其简单。
- **功能限制**：
  - 仅支持`GET`方法。
  - 无请求头（Headers）、状态码或错误处理。
  - 响应只能是纯文本（HTML）。
- **交互示例**：

```http 
GET /index.html
```


### 2.**HTTP/1.0（1996年，RFC 1945）**

- **主要改进**：
  - 引入**请求头/响应头**（Headers），支持元数据传输（如`Content-Type`、`Status Code`）。
  - 支持多种方法（`GET`、`POST`、`HEAD`）。
  - 新增状态码（如`200 OK`、`404 Not Found`）。
  - 支持非HTML内容（如图像、文件）。
- **缺点**：
  - **每个请求需建立新TCP连接**（无持久连接），高延迟。
  - 无主机头（Host header），无法虚拟主机托管。

### 3.**HTTP/1.1（1997年，RFC 2068；1999年更新为RFC 2616）**

- **核心改进**：
  - **持久连接（Keep-Alive）**：默认复用TCP连接，减少握手开销。
  - **管道化（Pipelining）**：**允许连续发送多个请求（但响应必须按顺序返回，易阻塞）。**
  - **Host头**：支持虚拟主机（同一IP托管多个域名）。
  - 新增方法（`PUT`、`DELETE`、`OPTIONS`等）。
  - **缓存控制（****`Cache-Control`****、****`ETag`****）**。
- **缺点**：
  - 队头阻塞（Head-of-Line Blocking）：一个慢请求会阻塞后续请求。
  - 头部冗余（未压缩）。

### 4.**HTTP/2（2015年，RFC 7540）**

- **基于Google的SPDY协议**，核心改进：
  - **二进制协议**：替代文本格式，解析更高效。
  - **多路复用（Multiplexing）**：**同一连接并行传输多个请求/响应，解决队头阻塞。**
  - **头部压缩（HPACK）**：减少冗余头部开销。
  - **服务器推送（Server Push）**：主动推送资源（如CSS/JS）。
  - 流优先级（Stream Prioritization）。
- **缺点**：
  - 仍依赖TCP，可能因TCP丢包重传导致延迟

### 5.**HTTP/3（2022年，RFC 9114）**

- **基于QUIC协议**（运行在UDP上）：
  - **解决TCP队头阻塞**：QUIC实现独立流的多路复用，丢包只影响单个流。
  - **0-RTT连接**：减少握手延迟（尤其对移动设备）。
  - **内置加密**（TLS 1.3为必需）。
  - 改进的拥塞控制。
- **注意**：HTTP/3不是HTTP/2的升级，而是底层协议从TCP切换到QUIC。

### **版本对比总结**

| 特性         | HTTP/1.0 | HTTP/1.1 | HTTP/2    | HTTP/3    |
| ---------- | -------- | -------- | --------- | --------- |
| **连接复用**​  | 不支持      | 持久连接     | 多路复用      | QUIC多路复用  |
| **协议层**​   | TCP      | TCP      | TCP       | UDP（QUIC） |
| **头部压缩**​  | 无        | 无        | HPACK     | QPACK     |
| **队头阻塞**​  | 存在       | 存在（TCP层） | TCP层存在    | 基本解决      |
| **服务器推送**​ | 不支持      | 不支持      | 支持        | 支持        |
| **加密**​    | 可选       | 可选       | 主流强制HTTPS | 强制TLS 1.3 |

### **选择建议**

- **兼容性优先**：HTTP/1.1（仍广泛支持）。
- **性能优化**：HTTP/2（适合现代浏览器和HTTPS场景）。
- **极致低延迟**：HTTP/3（适合高丢包网络，如移动端）。

各版本的演进始终围绕**降低延迟、提高安全性、优化传输效率**展开。实际应用中，HTTP/2和HTTP/3需服务端和客户端同时支持（如浏览器、CDN）。

### **总结三者关系**

- **连接复用**是**基础能力，解决重复握手问题。**
- **队头阻塞**是复用连接后的新挑战，推动协议升级（如HTTP/2多路复用、HTTP/3 QUIC）。
- **服务器推送**是性能优化手段，依赖多路复用实现高效并行传输。
