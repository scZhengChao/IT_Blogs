# **http/1.0->http/1.1连接复用（Connection Reuse）**

## 目录

- [是什么？](#是什么)
- [如何工作？](#如何工作)
- [对比版本](#对比版本)

#### **是什么？**

- **定义**：在同一个TCP连接上发送和接收多个HTTP请求/响应，避免重复建立和断开连接的开销。
- **解决的问题**：**早期HTTP/1.0每次请求都需要新建TCP连接（三次握手+四次挥手），高延迟且浪费资源**。

#### **如何工作？**

- **HTTP/1.1的持久连接（Keep-Alive）** &#x20;

  客户端和服务端通过请求头`Connection: keep-alive`明确复用连接，默认开启。 &#x20;

  **示例**：

```http 
GET /page1.html HTTP/1.1
Host: example.com
Connection: keep-alive

GET /page2.html HTTP/1.1
Host: example.com
Connection: keep-alive
```


- 两个请求通过同一个TCP连接发送，减少握手次数。
- **HTTP/2的多路复用（Multiplexing）** &#x20;

  进一步允许在同一个连接上**并行交错**传输多个请求/响应（二进制分帧），无需按顺序等待。

#### **对比版本**

| 版本       | 机制       | 效率               |
| -------- | -------- | ---------------- |
| HTTP/1.0 | 无复用      | 每个请求独立连接，高延迟。    |
| HTTP/1.1 | 持久连接（串行） | 复用连接，但请求必须按顺序处理。 |
| HTTP/2/3 | 多路复用（并行） | 真正并行，大幅提升效率。     |
