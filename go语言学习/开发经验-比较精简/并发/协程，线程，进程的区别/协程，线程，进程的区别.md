# 协程、线程、进程的区别

这是理解现代并发编程的核心概念。让我用一个**餐厅的比喻**来帮助你理解：

## 餐厅比喻

- **进程** = 整个餐厅
- **线程** = 餐厅里的服务员
- **协程** = 服务员同时处理多桌的技巧

## 详细对比

| 维度        | 进程         | 线程        | 协程           |
| --------- | ---------- | --------- | ------------ |
| **定义**​   | 程序执行实例     | 进程内的执行单元  | 用户态轻量级线程     |
| **资源拥有**​ | 独立内存空间     | 共享进程内存    | 共享线程栈，极小内存   |
| **切换开销**​ | 大（内核）      | 中（内核）     | 极小（用户态）      |
| **创建数量**​ | 几十\\\~几百个  | 几百\\\~几千个 | 几十万\\\~百万    |
| **通信方式**​ | IPC、Socket | 共享内存      | Channel、共享内存 |
| **调度者**​  | 操作系统       | 操作系统      | 用户/运行时       |
| **并发模型**​ | 多进程        | 多线程       | 协程池、事件循环     |
| **隔离性**​  | 强          | 弱（共享内存）   | 很弱           |
| **崩溃影响**​ | 不影响其他进程    | 导致整个进程崩溃  | 可能导致线程崩溃     |

## 深入解析

### 1. 进程（Process）

```c 
// Linux 创建进程
#include <unistd.h>
int main() {
    pid_t pid = fork();  // 创建子进程
    if (pid == 0) {
        // 子进程
        printf("Child process\n");
    } else {
        // 父进程
        printf("Parent process\n");
    }
}
```


**特点**：

- **操作系统资源分配的基本单位**
- 每个进程有独立的内存空间（4GB虚拟内存）
- 进**程间通信（IPC）复杂**
- 创建/销毁开销大

**示例**：

- 浏览器（主进程、渲染进程、GPU进程、插件进程）
- Chrome 多进程架构

### 2. 线程（Thread）

```java 
// Java 创建线程
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(() -> {
            System.out.println("Thread running");
        });
        thread.start();  // 启动线程
    }
}
```


**特点**：

- CPU 调度的基本单位
- **共享进程的内存空间**
- **有独立的栈，共享堆**
- 线程间通信简单但需同步
- 上下文切换仍需要内核参与

**问题**：

```java 
// 线程安全问题
public class Counter {
    private int count = 0;
    
    public void increment() {
        count++;  // 线程不安全！
    }
}
```


### 3. 协程（Coroutine/Goroutine）

```go 
// Go 创建协程
func main() {
    // 创建10万个协程
    for i := 0; i < 100000; i++ {
        go func(id int) {
            fmt.Printf("Goroutine %d\n", id)
        }(i)
    }
    time.Sleep(time.Second)
}
```


```python 
# Python 协程
import asyncio

async def hello():
    print("Hello")
    await asyncio.sleep(1)
    print("World")

# 运行10万个协程
async def main():
    tasks = [hello() for _ in range(100000)]
    await asyncio.gather(*tasks)

asyncio.run(main())
```


**特点**：

- 用户态线程，调度由运行时控制
- 极轻量（2KB vs 线程2MB）
- 非抢占式调度（协作式）
- 创建/切换开销极小
- 适合 I/O 密集型任务

## 内存模型对比

### 进程内存布局

```markdown 
进程A (4GB虚拟内存)        进程B (4GB虚拟内存)
┌─────────────────┐        ┌─────────────────┐
│ 代码段          │        │ 代码段          │
│ 数据段          │        │ 数据段          │
│ 堆              │        │ 堆              │
│ 栈 (主线程)     │        │ 栈 (主线程)     │
│ 共享库          │        │ 共享库          │
│ ...            │        │ ...            │
└─────────────────┘        └─────────────────┘
      独立内存空间                 独立内存空间
```


### 线程内存布局

```markdown 
进程 (4GB虚拟内存)
┌─────────────────────────────────────┐
│ 代码段                              │ ← 共享
│ 数据段                              │ ← 共享
│ 堆                                  │ ← 共享
├─────────────────────────────────────┤
│ 线程1栈 (1MB)  │ 线程2栈 (1MB)      │ ← 独立
│ 线程1寄存器    │ 线程2寄存器        │ ← 独立
│ 线程1局部变量  │ 线程2局部变量      │ ← 独立
└─────────────────────────────────────┘
```


### 协程内存布局

```markdown 
线程
┌─────────────────────────────────────┐
│ 协程1栈 (2KB) │ 协程2栈 (2KB)       │
│ 协程1寄存器   │ 协程2寄存器         │
│ 协程1上下文   │ 协程2上下文         │
│ ...          │ ...                 │
└─────────────────────────────────────┘
共享进程的所有内存资源
```


## 性能对比数据

| 操作        | 进程      | 线程      | 协程          |
| --------- | ------- | ------- | ----------- |
| **创建时间**​ | 1-3ms   | 0.1-1ms | 0.001-0.1ms |
| **内存占用**​ | 几MB-几GB | 1-8MB   | 2-8KB       |
| **切换开销**​ | 1-10μs  | 1-5μs   | 0.1-0.5μs   |
| **最大数量**​ | 几百      | 几千      | 几十万         |
| **通信延迟**​ | 高       | 中       | 低           |

## 选择建议

### 选择进程：

- 需要高隔离性（安全）
- 第三方库不是线程安全的
- 利用多核CPU计算
- 防止一个任务崩溃影响其他

### 选择线程：

- CPU密集型计算
- 需要利用多核
- 任务间需要共享数据
- 已有成熟的线程池实现

### 选择协程：

- 高并发I/O密集型（网络、磁盘）
- 需要数万以上并发连接
- 内存有限
- 快速任务切换
