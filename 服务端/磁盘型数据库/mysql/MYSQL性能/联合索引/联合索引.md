# 最左匹配&#x20;

![](image_wu9gP1ceo4.png)

走最\*\*左边的一个 key \*\*就可以走这个联合索引；不必全部匹配；

## 什么是联合索引的最左匹配原则？

最左匹配原则指的是：当使用联合索引时，MySQL会从索引\*\*的最左列开始向右匹配，直到遇到范围查询（****`>`****,****`<`****,****`between`****,`like`\*\***等）就停止匹配**。如果查询条件不包含联合索引的最左列，索引将不会被使用。

## 示例说明

假设我们有一个用户表，并创建了联合索引`INDEX idx_name_age_sex (name, age, sex)`：

```sql 
CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    age INT,
    sex CHAR(1),
    INDEX idx_name_age_sex (name, age, sex)
);

```


### 有效使用索引的情况（遵循最左匹配）

1. **全列匹配**- 使用所有索引列：

```sql 
SELECT * FROM users WHERE name = '张三' AND age = 25 AND sex = 'M';
```


*完全使用索引*

1. **从左开始连续匹配**：

```sql 
SELECT * FROM users WHERE name = '张三' AND age = 25;
```


*使用索引的前两列*

1. **仅使用最左列**：

```sql 
SELECT * FROM users WHERE name = '张三';
```


### 无法使用索引或部分使用索引的情况

1. **缺少最左列**：

```sql 
SELECT * FROM users WHERE age = 25 AND sex = 'M';
```


***无法使用索引（违反最左匹配原则）***

1. **中间缺少列**：

```sql 
SELECT * FROM users WHERE name = '张三' AND sex = 'M';
```


\*\* *只能使用name列的索引，*\*\* ​*sex列不会用到*

1. **范围查询后的列**：

```sql 
SELECT * FROM users WHERE name = '张三' AND age > 20 AND sex = 'M';
```


**name和age列会使用索引，** 但sex列不会（因为age是范围查询）

## 特殊情况

1. \*\*`like`\*\***查询**：
   - `LIKE '张%'`- **可以使用索引（前缀匹配）**
   - `LIKE '%三'`- 不能使用索引
2. **函数和计算**：

```sql 
SELECT * FROM users WHERE UPPER(name) = 'ZHANGSAN';
```


***使用函数会导致索引失效***

## 优化建议

1. **将选择性高的列放在左边**- 区分度高的列（如姓名）放在联合索引的左侧
2. **考虑查询频率**- 经常作为查询条件的列应该放在左侧
3. **避免过多索引列**- 联合索引的列数不宜过多（通常不超过3-5列）
4. **注意列顺序**- 根据实际查询需求设计合理的列顺序

## 如何验证索引使用情况

使用`EXPLAIN`命令查看查询执行计划：

```sql 
EXPLAIN SELECT * FROM users WHERE name = '张三' AND age = 25;
```


查看结果中的`key`和`key_len`字段可以确认是否使用了索引以及使用了多少索引列。

**理解并正确应用最左匹配原则，可以显著提高数据库查询性能，减少全表扫描的情况**。
