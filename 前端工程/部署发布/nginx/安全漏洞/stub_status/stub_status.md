# stub\_status

`Nginx`的`stub_status`模块是一个官方提供的一个用于**实时监控Nginx服务器状态信息的模块**。它通过`HTTP`接口提供了一个简单的页面，展示了当前`Nginx`服务器的**关键性能指标和连接状态。**

启用`stub_status`模块后，可以通过访问特定的URL来获取Nginx的状态信息。默认情况下，该URL为`http://your_server_ip/nginx_status`。

`stub_status`模块提供了以下关键的状态指标：

1. 连接统计：包括活跃连接数、接受连接数、处理请求数等。
2. 请求统计：包括总请求数、HTTP方法统计、响应状态码统计等。
3. 连接状态：包括每个连接的详细信息，如连接时间、请求方法、请求URI、客户端IP和当前处理状态等。

通过访问`stub_status`页面，管理员可以实时监控Nginx服务器的连接和请求情况，以及检查服务器的负载情况。这对于进行故障排除、性能优化和实时监控非常有用。

要启用`stub_status`模块，需要在Nginx的配置文件中添加以下配置块：

```nginx 
location /nginx_status {
    stub_status on;
    access_log off;
    allow 127.0.0.1;   # 限制只允许本地访问
    deny all;          # 阻止其他IP访问
}

```


请注意，**为了安全考虑，**建议将`stub_status`页面的**访问仅限制为本地或特定IP地址。**

总结起来，Nginx的`stub_status`模块提供了一种轻量级的方式，用于查看Nginx服务器的实时状态信息，并帮助管理员进行性能监控和故障排除。它是一个非常有用的工具，适用于运维和管理Nginx服务器。

在Nginx的`stub_status`模块中，有一些关键的状态参数，分别表示以下内容：

1. Active connections（活跃连接数）：表示当前与客户端保持活动状态的连接数。
2. server accepts handled requests（服务器接受、处理和请求数）：它是一个统计信息，包含以下三个值：
   - Accepts（接受连接数）：表示自服务器启动以来已经接受的连接总数。
   - Handled（处理连接数）：表示自服务器启动以来已经成功处理的连接总数。
   - Requests（请求数）：表示自服务器启动以来已经处理的请求数量。通常，一个连接可能会包含多个请求。

这些参数可以帮助管理员了解Nginx服务器的负载情况和处理能力。通过监视活跃连接数，可以判断当前服务器的连接状况是否正常。而接受、处理和请求数的统计信息，则提供了对服务器整体性能的评估。

在`stub_status`页面中，这些参数通常以类似如下的格式呈现：

```nginx 
Active connections: 100
server accepts handled requests
 10000 10000 20000

```


其中，第一行给出了活跃连接数。第二行以`server accepts handled requests`为标题，后面的数字分别对应于接受、处理和请求数的统计值。

这些参数不仅适用于实时监控，还可以用于识别系统负载过高或其他性能问题。通过比较这些值与服务器硬件和配置的极限，可以评估服务器的健康状况，并进行必要的调整和优化。

这些参数**并不反映某个特定时间段（例如秒、分钟或小时）内的统计数据，而是从服务器启动时开始到当前时间点的整体统计。**

如果您希望获取特定时间段内的连接和请求数量，可以使用其他工具或方法，**例如监控工具（如Prometheus、Grafana等）配合上述参数进行数据采集和图表展示，以便更好地了解Nginx服务器的性能和负载情况。**

> 另一个解决方案：删除stub\_status，坚决不配置即可；on/off 都不好；直接删除
