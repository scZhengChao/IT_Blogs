#### **是什么？**

- **定义**：服务端在客户端明确请求某个资源（如HTML）时，**主动推送其他依赖资源（如CSS/JS），减少额外请求的延迟。**
- **目标**：优化页面加载速度，避免“请求-等待”的往返时间（RTT）。

#### **如何工作？**

1. 客户端请求`index.html`。
2. 服务端返回`index.html`，同时通过`PUSH_PROMISE`帧告知客户端：“我要推送`style.css`和`script.js`”。
3. 客户端缓存推送的资源，后续解析HTML时直接使用，无需再请求。

#### **示例（HTTP/2）**

```http 
客户端请求：
GET /index.html HTTP/2

服务端响应：
HTTP/2 200 OK
-- 推送style.css--
PUSH_PROMISE: GET /style.css
-- 推送script.js--
PUSH_PROMISE: GET /script.js
```


#### **注意事项**

- **推送可能浪费带宽**：客户端已缓存资源时，仍需接收推送。
- **HTTP/3的改进**：QUIC协议优化了推送的可靠性，减少冗余。

#### **对比版本**

| 版本       | 支持情况   | 实现机制                    |
| -------- | ------ | ----------------------- |
| HTTP/1.1 | 不支持    | 需客户端主动请求依赖资源。           |
| HTTP/2   | 支持     | 通过\`PUSH\_PROMISE\`帧实现。 |
| HTTP/3   | 支持（优化） | 基于QUIC流，更高效。            |
