# 查询速度

在 JavaScript 中，对象（`Object`）的键值查询通常比数组（`Array`）的某些查询操作更快，这主要与底层数据结构的实现方式有关。以下是详细解释：

### **1. 底层数据结构差异**

- **对象（Object）** &#x20;

  现代 JavaScript 引擎（如 V8）会将对象优化为\*\*哈希表（Hash Table）**或**隐藏类（Hidden Class）\*\*结构。
  - **哈希表**：通过**哈希函数直接计算键的存储位置**，实现**O(1)** 时间复杂度的查询。
  - **隐藏类**：对相同结构的对象进行优化，**复用属性偏移量，减少重复计算。**
- **数组（Array）** &#x20;

  数组本质上是特殊的对象，但引擎会根据元素类型和密集程度动态优化为两种模式：
  - **快数组（Fast Elements）**：连续内存存储，通过索引直接访问（**O(1)**）。
  - **慢数组（Dictionary Elements）**：退化为哈希表（稀疏数组或非数值键时），查询效率与对象类似。

### **2. 查询场景对比**

#### **场景 1：键名/索引已知**

- **对象**：`obj[key]` &#x20;

  直接通过**哈希表或隐藏类偏移量访问**，**O(1)**。
- **数组**：`arr[index]` &#x20;

  快数组模式下同样为**O(1)**；两者速度相当。

#### **场景 2：查找值是否存在**

- **对象**：`key in obj`或`obj.hasOwnProperty(key)` &#x20;

  **哈希表直接查找键名**，**O(1)**。
- **数组**：`arr.includes(value)`或`arr.indexOf(value)` &#x20;

  需要遍历数组（**O(n)**），效率低于对象。

#### **场景 3：动态键名查询**

- **对象**：`obj[key]`（键名动态生成） &#x20;

  **哈希表仍能高效处理（哈希碰撞时退化为链表/红黑树，** 但概率极低）。
- **数组**：若使用`arr["customKey"]`形式（非数值索引），退化为慢数组，效率与对象接近。

### **3. 引擎优化策略**

- **对象优化**
  - **哈希表扩容**：当**哈希表负载因子过高时，自动扩容以减少碰撞。**
  - **隐藏类共享**：**相同结构的对象共享隐藏类，提升属性访问速度。**
- **数组优化**
  - **类型标记**：若数组元素类型一致（如全为数字），引擎会标记为特定类型（如`PACKED_SMI_ELEMENTS`），进一步优化访问速度。
  - **稀疏惩罚**：如果数组存在空洞（如`arr[1000000] = 1`），可能退化为慢数组，查询效率下降。

***

### **4. 性能测试对比**

```javascript 
// 对象查询
const obj = {};
for (let i = 0; i < 1e6; i++) obj[i] = i;
console.time("Object查值");
obj[999999]; // 直接访问
console.timeEnd("Object查值"); // ~0.01ms

// 数组遍历查值
const arr = [];
for (let i = 0; i < 1e6; i++) arr[i] = i;
console.time("数组遍历");
arr.includes(999999); // 需要遍历
console.timeEnd("数组遍历"); // ~5ms
```


### **5. 何时选择数组？**

- **有序数据**：需要保持元素顺序时（如队列、栈）。
- **数值索引**：频繁通过索引访问且数据密集时。
- **内置方法**：需要利用`map`、`filter`等数组方法时。

***

### **6. 替代方案：Map**

ES6 引入的`Map`结合了对象和数组的优点：

- 键名支持任意类型（对象、函数等）。
- **保持插入顺序。**
- **哈希表实现，查询效率****O(1)****。**
- 更适合动态增删键值对的场景。

### **总结**

| 数据结构 | 适用场景       | 查询效率（值是否存在）      | 内存占用     |
| ---- | ---------- | ---------------- | -------- |
| 对象   | 键值对、静态键名   | **O(1)** ​       | 较高（哈希表）  |
| 数组   | 有序集合、数值索引  | \*\*O(n)\*\*（遍历） | 较低（连续内存） |
| Map  | 动态键名、复杂键类型 | **O(1)** ​       | 中等       |

选择数据结构时需权衡**查询需求**、**数据特性**和**引擎优化机制**。对于纯查询场景，对象或`Map`是更优选择。
