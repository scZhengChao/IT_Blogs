在 Git 中，当你的本地分支落后于远程分支时（即"该分支已过期"），有两种主要方式来更新你的分支：**合并(merge)和**变基(rebase)。

## 1. 通过合并更新分支 (`git merge`)

### 基本用法

```bash 
git fetch origin          # 获取远程最新变更
git merge origin/branch    # 将远程分支合并到当前分支
```


### 特点

- 会创建一个新的合并提交
- 保留完整的历史记录
- 是非破坏性操作
- 适合多人协作的公共分支

### 示例工作流

```markdown 
A --- B --- C (origin/main)
 \
  D --- E (main)
  
执行 git merge origin/main 后：

A --- B --- C (origin/main)
 \         \
  D --- E -- M (main)
```


## 2. 通过变基更新分支 (`git rebase`)

### 基本用法

```markdown 
git fetch origin          # 获取远程最新变更
git rebase origin/branch   # 将当前分支变基到远程分支
```


### 特点

- 将本地提交"重新播放"在远程分支之上
- 产生线性的历史记录
- 会重写提交历史
- 适合个人开发的分支

### 示例工作流

```markdown 
A --- B --- C (origin/main)
 \
  D --- E (main)
  
执行 git rebase origin/main 后：

A --- B --- C (origin/main)
           \
            D' --- E' (main)
```


## 比较表格

| 特性   | 合并 (merge)        | 变基 (rebase)     |
| ---- | ----------------- | --------------- |
| 历史记录 | **保留原始结构，有合并提交**​ | **线性历史，无合并提交**​ |
| 提交哈希 | 保留原始提交哈希          | 创建新的提交哈希        |
| 适用场景 | 公共分支，多人协作         | 个人分支，准备合并前      |
| 安全性  | **非破坏性操作**​       | **会重写历史，需谨慎**​  |
| 冲突处理 | 一次性解决所有冲突         | 可能需要多次解决相同冲突    |

## 何时使用哪种方式

1. **使用合并**：
   - 更新公共分支（如 main/master）
   - 多人协作的分支
   - 当你想要明确显示分支合并的历史
2. **使用变基**：
   - 在将个人分支合并到主分支之前
   - 保持干净的线性历史
   - 解决分支分叉时间过长的问题

## 高级技巧

### 交互式变基

```bash 
git rebase -i origin/branch
```


可以编辑、重排、合并或删除提交

### 强制推送（变基后）

```bash 
git push --force-with-lease
```


注意：只对个人分支使用强制推送

## 最佳实践建议

1. 对公共分支总是使用合并
2. 对个人分支可以使用变基来保持整洁
3. 变基后推送时使用`--force-with-lease`比`--force`更安全
4. 在变基前先备份分支（创建临时分支）

记住：**已经推送到远程的分支不要变基**，除非你确切知道自己在做什么并且与协作者协调好。
