# 为什么把 \<script> 放在最后可以避免阻塞渲染？

HTML 解析器（浏览器解析 HTML 的组件）在遇到`<script>`标签时，默认会**停止 HTML 解析**，先下载并执行该脚本，然后再继续解析后面的 HTML。这就是所谓的 **“脚本阻塞渲染”**（Script Blocking）。

如果`<script>`标签放在`<head>`中或页面较靠前的位置，浏览器在下载和执行 JS 期间，**无法继续解析下面的 HTML**，也就无法构建 DOM 树、渲染页面内容，导致用户看到一个“空白页面”或“长时间白屏”。

而如果把`<script>`标签放在页面**最底部**（`</body>`之前），HTML 文档的大部分内容已经解析完成，DOM 树也基本构建好了，这时再执行 JS，就不会影响页面的初始渲染了。

***

## 🧠 举个例子对比

### ❌ 不推荐的写法（JS 在头部，会阻塞渲染）

```html 
<!DOCTYPE html>
<html>
<head>
  <title>示例</title>
  <script src="app.js"></script> <!-- JS 在头部，会阻塞 HTML 解析 -->
</head>
<body>
  <h1>你好，世界！</h1>
</body>
</html>
```


在这种情况下，浏览器会先下载并执行`app.js`，在此期间不会解析`<h1>`标签，用户可能会看到一个空白页面，直到 JS 执行完毕。

### ✅ 推荐的写法（JS 在底部，不阻塞初始渲染）

```html 
<!DOCTYPE html>
<html>
<head>
  <title>示例</title>
</head>
<body>
  <h1>你好，世界！</h1>
  <script src="app.js"></script> <!-- JS 在底部，不会阻塞 HTML 解析 -->
</body>
</html>
```


**在这种情况下，浏览器会先解析并渲染**\*\*`<h1>`\*\***标签**，用户可以立即看到页面内容，然后再下载并执行`app.js`。这样用户体验更好，尤其是当 JS 文件较大或网络较慢时。

## ⚠️ 注意事项

虽然把`<script>`放在最后可以避免阻塞**初始渲染**，但它**仍然会阻塞后续的 HTML 解析**（如果 JS 还没下载完的话）。不过因为此时大部分页面已经渲染完成，对用户体验影响较小。

另外，现代前端开发中，我们通常还会结合以下技术进一步优化：

1. **使用**\*\*`async`****或****`defer`\*\***属性**（下面会介绍）
2. **服务端渲染（SSR）**
3. **代码拆分（Code Splitting）**
4. **懒加载（Lazy Loading）**

***

## 🚀 更高级的优化：`async`和`defer`

除了把`<script>`放在最后，你还可以使用`async`或`defer`属性来控制脚本的加载和执行行为：

| 属性        | 是否阻塞 HTML 解析 | 执行时机             |
| --------- | ------------ | ---------------- |
| 无属性       | 阻塞           | 下载完立即执行          |
| \`async\` | 不阻塞          | 下载完立即执行（顺序不确定）   |
| \`defer\` | 不阻塞          | 等 HTML 解析完再按顺序执行 |

### 使用`defer`的例子：

```html 
<script src="app.js" defer></script>

```


- \*\*`defer`\*\***脚本会在 HTML 解析完成后、DOMContentLoaded 事件前按顺序执行。**
- 适合那些依赖 DOM 或需要按顺序执行的脚本。

### 使用`async`的例子

```html 
<script src="app.js" async></script>
```


- `async`脚本一旦下载完成就会立即执行，不保证顺序。
- 适合那些独立的、不依赖 DOM 或其他脚本的代码（比如统计分析脚本）。

***

## ✅ 总结

- **把**\*\*`<script>`****标签放在页面最后（****`</body>`\*\***前）确实可以避免它阻塞页面的初始渲染**，是一种简单有效的优化手段。
- 更推荐结合`defer`或`async`属性来进一步优化脚本加载行为，尤其是在现代前端项目中。
- 如果对首屏性能要求非常高，还可以考虑服务端渲染（SSR）等更高级的方案。

如果你正在开发一个注重性能的网站，这些技巧都非常实用！
