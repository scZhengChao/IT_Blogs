# prefetch和preload:

- **preload强制浏览器获取当前需要的资源，优先级高，**
- **prefetch获取将来需要的资源， 把决定权留给浏览器， 所以一般浏览器会在闲置的时候下载， 优先级最低。**

## 总结：

**总结就是preload一定会及时下载资源， prefetch最后都不一定去下载**

`preload`和`prefetch`是两种资源提示（Resource Hints），用于优化脚本（`<script>`）和其他资源的加载性能，但它们的**使用场景**和**优先级**有显著差异。以下是详细对比：

### **1.****`preload`****（预加载当前页面关键资源）**

#### **作用**

- **立即以高优先级加载资源**，确保在当前页面中使用时已缓存。
- 适用于**渲染关键路径**中的脚本（如首屏依赖的 JS）。

#### **对**\*\*`<script>`\*\***的影响**

- **加载优先级**：`High`（与页面渲染阻塞资源同级）。
- **执行时机**：仅预加载，**不自动执行**，需通过`<script>`标签或动态插入执行。
- **适用场景**：
  - 提前加载关键脚本（如框架、主业务代码）。
  - 配合`as="script"`明确资源类型。

#### **代码示例**

```html 
<!-- 预加载脚本（不执行） -->
<link rel="preload" href="critical.js" as="script">

<!-- 后续通过 script 标签执行 -->
<script src="critical.js"></script>
```


#### **注意事项**

- **必须指定**\*\*`as`\*\***属性**（如`as="script"`），否则可能重复加载。
- 滥用会导致带宽浪费（仅预加载真正关键的资源）。

### **2.****`prefetch`****（预加载下一页可能需要的资源）**

#### **作用**

- **以****低优先级****在空闲时加载资源**，预缓存供后续页面使用。
- 适用于**非关键资源**或**未来导航可能需要的脚本**。

#### **对**\*\*`<script>`\*\***的影响**

- **加载优先级**：`Low`（**浏览器空闲时加载**）。
- **执行时机**：**不执行，仅缓存到磁盘。**
- **适用场景**：
  - 预加载下一页的脚本（如路由分块后的 JS）。
  - 提前缓存用户可能操作的功能脚本（如弹窗、懒加载模块）。

#### **代码示例**

```html 
<!-- 预加载未来可能需要的脚本 -->
<link rel="prefetch" href="next-page-bundle.js" as="script">
```


#### **注意事项**

- **不适合当前页面关键资源**（优先级太低，可能来不及加载）。
- 移动端需谨慎使用（可能浪费用户流量）。

### **核心差异对比**

| 特性        | \`preload\`          | \`prefetch\` |
| --------- | -------------------- | ------------ |
| **加载时机**​ | 立即（高优先级）             | 空闲时（低优先级）    |
| **目标**​   | 当前页面关键资源             | 未来页面/非关键资源   |
| **缓存位置**​ | 内存缓存                 | 磁盘缓存         |
| **是否执行**​ | 需手动通过\`\<script>\`执行 | 仅缓存，不执行      |
| **滥用后果**​ | 阻塞带宽，影响当前页面性能        | 浪费预取带宽       |

### **使用建议**

#### **何时用**\*\*`preload`？\*\*​

- 首屏渲染依赖的脚本（如 React/Vue 核心包）。
- 关键异步脚本（如`async`但需尽早加载的库）。

#### **何时用**\*\*`prefetch`？\*\*​

- 路由分块后的脚本（如 SPA 的其他路由组件）。
- 用户可能触发的功能脚本（如点击后才加载的模态框 JS）。

### **实际案例**

#### **场景 1：优化首屏加载**

```html 
<!-- 预加载关键框架 -->
<link rel="preload" href="react.production.min.js" as="script">
<!-- 主业务代码 -->
<script src="app.js"></script>

<!-- 预 prefetch 其他路由 -->
<link rel="prefetch" href="dashboard-chart.js" as="script">
```


#### **场景 2：动态加载优化**

```javascript 
// 用户 hover 按钮时预 prefetch 脚本
document.getElementById('btn').addEventListener('mouseover', () => {
  const link = document.createElement('link');
  link.rel = 'prefetch';
  link.href = 'modal.js';
  link.as = 'script';
  document.head.appendChild(link);
});
```


### **兼容性**

- 现代浏览器均支持（包括 IE11+ 的有限支持）。
- 可通过`<script>`的`rel="modulepreload"`预加载 ES 模块。

***

### **总结**

- \*\*`preload`= \*\*​**紧急加载当前页关键脚本**（“现在就要用”）。
- **`prefetch`****=**** 闲时加载未来脚本**（“下次可能会用”）。
- 两者均需配合`<script>`标签执行，**仅优化加载时机**，不改变执行逻辑。
