Chrome 的「Override content」（也常称「本地覆盖」）本质是：**将浏览器请求的资源（包括接口返回、JS/CSS 文件、页面 HTML 等）映射到本地文件，当浏览器发起请求时，** 会优先加载本地文件的内容，而非服务器返回的内容。

对于接口返回的覆盖，核心是**拦截接口请求 → 替换响应内容**，无需修改后端代码即可模拟各种返回场景（如成功 / 失败、异常数据、边界值等）。

### 二、分步实操（覆盖接口返回）

以下是完整的操作步骤，以 Chrome 120+ 版本为例（不同版本界面略有差异，但核心逻辑一致）：

#### 步骤 1：开启开发者工具并进入「Overrides」面板

1. 打开 Chrome，按`F12`/`Ctrl+Shift+I`（Mac 是`Cmd+Opt+I`）打开开发者工具；
2. 点击开发者工具顶部的「More tabs」（⋮ 图标）→ 选择「More tools」→ 「Overrides」（或直接在开发者工具中按`Ctrl+Shift+P` 输入「Overrides」快速定位）；
3. 在「Overrides」面板中，点击「Select folder for overrides」，选择本地一个**空文件夹**（用于存放要覆盖的接口返回文件，Chrome 会要求授予该文件夹的读写权限，需允许）。

#### 步骤 2：捕获并保存要覆盖的接口请求

1. 切换到开发者工具的「Network（网络）」面板；
2. 触发目标接口请求（比如刷新页面、点击按钮，确保接口出现在 Network 列表中）；
3. 找到目标接口（可通过「Filter（筛选）」输入接口路径 / 关键词快速定位），右键该接口 → 选择「Save for overrides」或者overrides content：
   - Chrome 会自动将该接口的请求 / 响应信息保存到你步骤 1 选择的本地文件夹中（文件夹内会生成与接口路径对应的目录和文件）。

#### 步骤 3：修改本地文件（覆盖接口返回内容）

1. 打开你步骤 1 选择的本地文件夹，找到刚保存的接口文件（通常是无后缀的文本文件）；
2. 用编辑器（如 VS Code）打开该文件，修改其中的响应内容（比如将`{"code":200,"data":[]}`改为`{"code":200,"data":[{"id":1,"name":"测试数据"}]}`）； **也可以直接在浏览器上编辑**，别忘了保存
   - 注意：需保持 JSON 格式合法（若接口返回是 JSON），否则浏览器解析会报错。

#### 步骤 4：启用覆盖并验证效果

1. 回到 Chrome 开发者工具的「Network」面板，确保「Enable overrides」（覆盖开关，在「Overrides」面板顶部 / Network 面板的筛选栏旁）已勾选；
2. 再次触发目标接口请求（刷新 / 点击按钮），此时 Chrome 会优先加载你本地修改后的文件内容，而非服务器返回的内容；
3. 验证：在「Network」面板中点击该接口，查看「Response（响应）」标签，会显示你本地修改后的内容，前端页面也会基于该内容渲染。
